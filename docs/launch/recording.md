## Capture setup

Use a disposable, minimal project containing a greeting function and a deterministic test. No user repository, remote origin, personal username, provider account screen or environment files should appear. Use a validated Apple Silicon/CLI combination from ../STATUS.md. Record the actual OS, CLI version, model, effort, execution mode and recording date in the asset manifest. The maker signs in privately before capture; never film authentication. Keep safety/approval gates enabled.

Prompt: “Change the greeting to accept a name, update its test, and explain the changes.” For Japanese capture use: 「名前を指定できるあいさつ関数に変更し、テストを更新して変更点を説明してください。」

Capture a real request, streamed reply, actual diff, explicit apply and resulting file. Show test success only if supported and actually run; otherwise keep “not verified” visible. Prefer one raw capture per UI language. Never translate provider output into a fabricated response. Capture failures honestly; retry and film a successful run rather than hiding an unresolved failure.

## 60-second edit

0–6: character and project context. 6–14: sticker inserts request, edit before sending. 14–22: CLI settings and execution approval. 22–36: real response and working-copy change. 36–49: inspect actual diff and explicitly apply. 49–55: actual result, verification status unchanged. 55–60: repo URL, supported Apple Silicon setup and source-build alpha label.

## 15-second edit

0–3: character and project. 3–6: editable sticker request. 6–10: actual response. 10–13: actual reviewed change. 13–15: repository and source-build alpha label.

These timings are editorial targets. Trim waits with an on-screen “Wait shortened” / 「待ち時間を短縮」 indicator whenever shortened. Do not suggest a 60-second real runtime. Retiming subtitles to the final footage is mandatory. Export 1920×1080 H.264 MP4; keep one language per video. Review subtitles at mobile viewing size.
